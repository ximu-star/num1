合同审批助手

基于电商小二 Harness 框架 + 掌柜智库 MinerU 解析能力改造而成

📌 项目概览

做什么：自动从飞书审批拉待办合同 → 解析 → 规则审查 → 风险报告回写评论区

核心价值：法务不用每份合同都从头审，AI 先跑一遍规则，标出风险点

技术栈：FastAPI + SQLAlchemy + PostgreSQL + Milvus + MinIO + MinerU

📦 三大服务

1️⃣ contract-review-service（业务服务，端口 8001）

全新代码 电商小二和掌柜智库都没有

文件功能说明
services/scheduler.py定时任务每 60 秒拉一次飞书待办
services/pipeline.py预处理流水线拉待办→下附件→解析→存库
services/parser.py合同解析PDF 走 MinerU，Word 走 python-docx
services/rules.pyPG 确定性规则正则+阈值，匹配合同风险点
services/review.py审查逻辑跑规则→生成摘要→生成评论
services/state_machine.py状态机pending/parsing/ready/reviewing/blocked/done
services/writeback.py回写飞书把审查意见写回审批评论区
models.py8 张数据表审批任务/附件/解析/规则/命中/结果/日志
clients/feishu.py飞书客户端Mock + Real 占位
clients/mineru.pyMinerU 解析来自掌柜智库
clients/storage.pyMinIO 存储合同附件存 MinIO

2️⃣ ai-service（AI 服务，端口 8002）

来自电商小二 改了业务逻辑

文件功能说明
harness/rules/fact.py事实校验提取合同金额/比例/天数，对比工具结果
harness/rules/action.py动作校验只允许 WRITE_COMMENT
harness/rules/correction.py重试机制校验失败自动重试 1 次
harness/skills/catalog.py4 个 Skill拉待办/解析/规则审查/报告回写
harness/tools/contract.py合同 Tool调业务服务的接口
harness/validator/answer.py结构校验输出格式必须符合五段式

3️⃣ frontend（管理后台前端）

来自电商小二 改了页面内容

定位：普通法务在飞书看评论，不登录这个系统。这个前端只是管理员看任务状态、重试 blocked 任务、维护规则用的。

🛡️ Harness 校验层（来自电商小二）

Harness 的作用：不是帮 AI 选 Tool，而是校验 AI 的输出不能胡说、不能乱操作。

1️⃣ 事实校验（fact.py）

原理：从 AI 回复里用正则提取事实 → 和工具返回的结果对比

提取的事实：

  • 金额（合同金额/总价）
  • 比例（预付款/付款比例/质保金）
  • 天数（账期/工期）
  • 条款号（第X条）
  • 规则编码（R-BUSINESS-001）

如果 AI 说的数字在工具结果里找不到 → 判定为编造 → 重试

2️⃣ 动作校验（action.py）

原理：只允许写回评论，不允许其他写操作

4 条规则：

  • 回写前必须确认任务状态是 reviewing
  • 同一 task + version 不能重复回写
  • 回写内容必须非空，不超过 3000 字
  • 回写失败进 blocked，不能谎称成功

3️⃣ Skill 设计（skills/catalog.py）

4 个 Skill：

Skill包含的 Tool
APPROVAL_FETCHlist_pending_approvals / get_approval_detail / download_attachment
CONTRACT_PARSEparse_contract / get_approval_detail
RULE_REVIEWrun_pg_rules / search_manual_semantic / get_approval_detail
REPORT_WRITEBACKsave_result / write_comment / get_approval_detail

🗄️ 数据来源（两路规则匹配）

PG 确定性规则

存在 PostgreSQL 的 review_rules 表
关键词匹配 + 阈值比较
例：付款天数 > 30 天、预付款 > 30%
优点：准确、可控
缺点：死板、只能匹配预设规则

Milvus 语义检索

造价规范手册切片存 Milvus
语义相似度匹配
例：合同里有"争议解决"→ 找手册里的争议解决条款
优点：灵活、能匹配没预设的规则
缺点：可能不准、需要人工复核
